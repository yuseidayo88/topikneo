# エラー・状態表示の方針（KLA）

アプリ内でユーザーに伝える失敗・オフライン・検証エラーを、次のように使い分けます。

## 0. 状態表示の優先順位（統一ルール）

- `offline`（通信必須操作ができない）  
- `fatal error`（画面継続不能）  
- `loading`（初回読込）  
- `empty`（データなし）  
- `content`（通常表示）

画面ごとにこの順序を崩さないことで、ユーザーが「今なにが起きているか」を迷わず判断できます。

## 1. 画面内ブロック（Banner / Block）

- **ネットワーク未接続・読み込み失敗**など、**その画面を続けられない／注意が必要**なとき。
- 例: チャットの再接続バナー、オフライン時の送信抑止（入力無効＋説明テキスト）。
- **原則**: 操作のたびにダイアログを出さず、**状態が分かる UI を常時または該当エリアに表示**する。

## 2. Alert（モーダル）

- **ユーザー操作の直後の結果**（成功・失敗）で、**1 回きりのフィードバック**が適切なとき。
- 例: 購入失敗、復元失敗、設定のリセット確認、ログイン失敗、フォーム検証エラー。
- **破壊的操作**（アカウント削除など）は必ず確認 Alert を挟む。

## 3. Toast / Snackbar（将来）

- 軽い成功・失敗を**閉じなくてよい**形で出したい場合。現状は Alert や画面内テキストで代替。

## 4. 開発時（`__DEV__`）

- `logEvent` は開発時に `[analytics]` として `console.log` する。本番では Analytics SDK 等に接続する想定。

## 5. オフライン時の操作

- **課金・サーバー同期が必要な操作**は `useNetInfo` 等でオフラインを検知し、**実行前に Alert またはボタン無効化**で抑止する（チャット送信・サブスク購入など）。
- 単語/文法などの初回データ取得中は、**暫定値（テスト値）を表示しない**。`読み込み中` 表示を優先し、取得完了後に件数・進捗を表示する。
