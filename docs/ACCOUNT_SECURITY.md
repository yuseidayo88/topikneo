# アカウント・セキュリティ（メール変更・パスワード変更・アカウント削除）

アカウント画面では次の操作ができます。

- **メールアドレスを変更** … 新しいメールに確認リンクが送られ、そこで承認すると変更されます（Supabase の「Secure email change」設定に依存）。
- **パスワードを変更** … メールでサインアップしたユーザーはパスワードを変更できます。Apple/Google のみで登録したユーザーも、ここでパスワードを設定するとメールログインが可能になります。
- **アカウントを削除** … 削除するとログイン情報やアプリ内データは復元できません。

## 他アプリでの「認証解除」の扱い

- **ログアウト** … どのアプリでも「ログアウト」でいったん認証を解除し、再度ログインする形です。KLA も同じです。
- **アカウントを削除** … 「認証を解除したい」の先として、多くのアプリでは「アカウントを削除」を用意しています。削除するとそのサービスとの紐づけがなくなり、実質的に「認証解除」になります。
- **連携解除だけ** … 「Google/Apple との連携だけ外して、メールログインは残す」のような細かい連携解除は、Supabase Auth の仕様上、標準では提供されていません。必要な場合は、削除してからメールで再登録する運用になります。

KLA では「ログアウト」と「アカウントを削除」の 2 つを用意しています。

## アカウント削除を動かすには（Edge Function）

アプリの「アカウントを削除」は、Supabase の **Edge Function** を呼び出します。  
Function をデプロイしていない場合は「削除に失敗しました」となり、案内文で「Dashboard の Authentication → Users から手動で削除できます」と表示されます。

### 手順（Supabase CLI 利用時）

1. プロジェクトで `supabase functions new delete-user` を実行し、`delete-user` 用の Function を作成します。
2. 中身で、リクエストの Authorization ヘッダーから JWT を取得し、`supabase.auth.getUser(jwt)` でユーザー ID を特定します。
3. **Service Role Key** を使う Admin クライアントで `auth.admin.deleteUser(uid)` を実行します（Service Role はクライアントに渡さず、Edge Function 内だけで使います）。
4. `supabase functions deploy delete-user` でデプロイします。

未デプロイの間は、削除したいユーザーは Supabase Dashboard → **Authentication** → **Users** から手動で削除してください。

## 運用チェック（セキュリティ）

### 1) 環境変数の取り扱い

- `.env` はローカル専用。リポジトリにコミットしない。
- `EXPO_PUBLIC_*` はクライアントに露出する前提。秘密情報（Service Role Key 等）は絶対に含めない。
- 秘密鍵は Supabase 側でローテーションし、アプリ側は必要な公開キーのみ更新する。

### 2) 依存パッケージ監査

- 定期的に `npm audit` を実行し、`high` / `critical` は優先対応する。
- 依存更新後は最低限、ログイン・単語/文法ロード・課金導線・チャット送信を再確認する。

### 3) レート制限・不正利用対策

- 認証系・チャット送信系はサーバー側（Supabase / Edge Function）でも制限を設ける。
- クライアント側のバリデーションは UX 改善目的。最終防御はサーバー側で行う。
